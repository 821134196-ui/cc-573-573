# 园区团餐配送批次与收餐核对系统

厨房、配送员、企业前台围绕**同一餐次批次**核对装箱、送达与签收数量；少餐、错餐沿原批次补送与复核，保证餐盒数量全程对得上账、不凭空增加或消失。

## 一条命令启动

```bash
./run.sh
# 打开 http://localhost:8080/app/
```

脚本会自动完成：前端依赖安装 → Vue 构建（产物通过 `go:embed` 打进二进制）→ Go 编译 → 启动。
数据落在 `data/mealcheck.db`（SQLite，首次启动自动建表与种子数据）。

- 自定义：`ADDR=:9090 DB_PATH=/tmp/x.db ./run.sh`
- 前端热更新开发：`./run.sh --dev`（Vite :5173 代理到后端 :8080）
- 仅验证：`bash scripts/verify.sh`（Go 单测 + HTTP 端到端核对）

## 演示账号（本地模拟登录，无密码）

| 账号 | 角色 | 能做什么 |
|---|---|---|
| `kitchen` | 厨房 | 按企业/餐次生成装箱清单、编辑、封箱登记封签 |
| `c1` `c2` `c3` | 配送员（北/南/机动线） | 接收、出发、送达、无人签收、封签破损上报 |
| `desk1` `desk2` | 企业前台 | 并列核对应收/实收/差额、签收、提差异 |
| `reviewer` | 运营复核 | 批准/驳回差异，分配补送/损失/退款，支付回执入账 |
| `admin` | 调度 | 指派路线、途中改派（兼复核） |

## 业务规则如何落地

**批次与装箱**
- 一个企业 + 一个日期 + 一个餐次只能有一个**原批次**；少餐补送不允许另建无关订单。
- 封箱前厨房可编辑装箱数；**封箱后任何角色都不能改装箱数量**（前台接口只允许填实收）。
- 每个保温箱登记唯一封签号；封签破损单独登记并自动生成待复核差异。

**路线与交接**
- 改派 = 旧路线任务置 `reassigned`（`active=false`）+ 新任务生效。
- 数据库有部分唯一索引兜底：`UNIQUE(batch_id) WHERE active=1`，同一批餐物理上不可能在两条路线同时显示在途/完成；旧配送员改派后无权继续操作。
- 接收、交接、出发、送达、改派、封签破损、无人签收全部写入 `route_events` 与审计时间线。

**签收与差异**
- 签收回执每行并列保存**应收（取自厨房装箱清单，服务端填充，忽略前端篡改）**、实收、差额。
- 实收 > 装箱直接 400 拒绝——餐盒不能凭空增加。
- 少盒/错餐/封签异常在签收时自动生成差异单；前台可补充提差异，但一个批次同时只有一张待处理差异单，防止重复报差把数量翻倍。
- 错餐实物不属于本批次树产出，单独平衡：`错餐签收 = 暂扣 + 退回厨房 + 驳回自留`，绝不计入正常实收。

**差异复核（数量依据）**
- 每条短少行必须满足 `补送 + 损失 + 退款 == 短少数`，逐行强制，否则整笔回滚。
- 批准补送会在**原批次树**下创建子批次（`root_id/parent_id/source_discrepancy_id` 溯源），补送批次按明细核对，实际装箱超过批准份数时封箱被守恒闸门拦截。
- 复核在数据库事务内立即跑守恒校验，不平衡就回滚；整棵树无在途批次、无待复核差异时自动关闭。

**退款幂等（模拟支付）**
- 退款单以 `refund-resolution-<id>` 为幂等键，唯一索引去重。
- 支付回执重复推送只返回“已入账”，金额不会第二次记账；已入账总额可按批次树汇总核对。

## 数量守恒模型

对每棵批次树（原餐次 + 各次补送）恒成立：

```
厨房装箱产出 = 正常实收 + 在途 + 待复核差异 + 争议驳回
             + 损失核销 + 待入账退款 + 已入账退款 + 已补送核销
```

- draft 补送批次只是“装箱计划”，餐盒未物理成型，不计入产出，仅展示。
- 另校验：`补送实际装箱 ≤ 复核批准份数`（按餐品），`错餐签收 = 暂扣+退回+自留`。
- 批次详情页有实时守恒面板（`GET /api/batches/:id/conservation`）。

## 技术栈与结构

- Go 1.23 + Gin + GORM + SQLite（纯 Go 驱动 `glebarez/sqlite`，无需 CGO）
- Vue 3 + Vite，前端嵌入单一二进制
- 配送与支付均为本地模拟：路线状态机在库内闭环，支付通道为带幂等键的 pending/posted 退款单

```
cmd/server/         启动入口
internal/models/    领域模型与状态常量
internal/store/     SQLite 打开、迁移（含部分唯一索引）、种子
internal/service/   装箱/封签/路线/签收/复核/支付 与数量守恒器（核心）
internal/api/       Gin 路由、角色中间件、嵌入静态资源
web/src/            Vue：四个角色工作台 + 批次详情/守恒面板/时间线
scripts/verify.sh   一键全量验证
scripts/e2e_check.py HTTP 端到端核对脚本
```

## 已验证场景

`go test ./...`（12 个用例）+ HTTP E2E（37 个调用断言）覆盖：

1. 装箱与签收数量相符 → 自动关闭；
2. 前台改装箱被拒、封箱后厨房也不能改、实收超装箱被拒；
3. 少盒签收 → 差异待复核，`装箱=实收+待复核`；
4. 途中改派旧段关闭/新段生效、唯一 active（应用层 + DB 索引双重保证）、旧配送员被拒；
5. 复核分配对不上短少数被拒且保持 open；补送沿原批次树、退款待入账；
6. 补送批次封箱→配送→全量签收，最终 `产出32 = 实收29 + 补送核销2 + 退款1`；
7. 重复退款回执只入账一次；
8. 错餐盒单独平衡、不能借错餐行补送/退款；
9. 封签破损、无人签收全程留痕，无人签收后改派二次送达；
10. 复核驳回短少计入争议且不产生退款；
11. 补送批次超批准份数封箱被拦截；
12. 同企业同餐次禁止另建原批次、角色越权被拒。
